# Income statement

A small React + Express income statement for Northwind Coffee Roasters, built from the supplied ledger. No database, credentials, or external services are required.

## Run

Requires Node.js 22.12 or newer. Verified with Node.js 26.0.0 and npm 11.12.1.

```sh
npm ci
npm test
npm run build
npm start
```

Open http://127.0.0.1:3000. The initial report covers January 1–March 31, 2026. Choose dates, then select **Generate statement**. Changing inputs alone does not change the displayed report.

For development, use two terminals:

```sh
npm run server
```

```sh
npm run dev
```

Open the Vite URL (normally http://127.0.0.1:5173). Vite proxies the API to port 3000. The built app needs only `npm start`. `PORT=3001 npm start` changes the built-app port; the development proxy remains configured for 3000.

Locked direct dependencies: Express 5.2.1, React/React DOM 19.3.0, Vite 8.3.1, React Vite plugin 6.1.1. `npm ci` uses the committed lockfile.

## API

```sh
curl 'http://127.0.0.1:3000/income-statement?start=2026-01-01&end=2026-03-31'
```

The response includes company, currency, period, account lines and totals for `revenue`, `costOfGoodsSold`, `operatingExpenses`, and `otherIncome`, plus `grossProfit`, `operatingIncome`, and `netIncome`. Every monetary value is an exact two-decimal string, such as `"-44480.14"`.

Dates must be single, real Gregorian `YYYY-MM-DD` values (years 0001–9999), with start on or before end. Both dates are included. Missing, repeated, invalid, or reversed dates return HTTP 400:

```json
{"error":{"code":"INVALID_DATE_RANGE","message":"Start date must be on or before end date."}}
```

Periods without income-statement activity return HTTP 200 with all relevant accounts at zero.

## Structure and verification

- `ledger.json`: unchanged supplied data, loaded and validated once at startup.
- `server/ledger.js`: account references, classifications, dates, amounts, statuses, and balanced-entry validation.
- `server/statement.js`: pure calculation independent of Express or React.
- `shared/money.js`: decimal strings ↔ BigInt cents; exact display formatting without floating-point conversion.
- `server/dates.js`: timezone-free calendar validation, also reused by the form.
- `server/app.js`: HTTP adapter; `server/index.js`: startup and built-page serving.
- `client/`: date form, request state, and semantic report table. No financial calculations in React.
- `tests/`: money, dates, ledger validation, calculations, real HTTP requests, and startup regression tests. Q1 expected values are a fixed independent tabulation, not generated by the calculator under test.

Browser acceptance checks cover Q1, March, changing dates before submission, empty periods, invalid ranges, failed-request retention, native keyboard input, and phone-width layout. Browser checks are manual; `npm test` runs the automated Node suite.
